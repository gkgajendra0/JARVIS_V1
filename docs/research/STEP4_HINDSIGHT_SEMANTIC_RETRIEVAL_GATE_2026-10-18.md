# Step 4 — Hindsight semantic retrieval and answer safety gate (research only)

**Date:** 2026-10-18  
**Status:** Offline protocol + scorer only; *no Hindsight recall has been measured in this PR*.  
**Depends on:** Draft PR #275 at `587fc176`, five pinned fictional facts, owner-machine successful single synthetic transfer-import on Hindsight API 1.0.0 (`79ffeebec009951ce3a42a2e48f5abbc94aa4120f4c6badb5c430a89d5f90acd`).

## Question being tested

Can a separately deployed, local Hindsight **retrieval** layer surface *enough authenticated facts* for JARVIS to answer reliably, without confusing:

- A correction (Atlas workshop originally Saturday, **corrected** to Sunday);
- A historical state change (Nile report Monday in an earlier state, Thursday later; previous state was not merely an erroneous statement);
- An unrelated independent fact (Atlas workshop in Hall B);
- Unknown information (Atlas start time not supplied);
- An ambiguous statement that was never admitted as a fact.

An archive that imports and reads back perfectly is **not** proof that recall ranks evidence correctly, much less that an assistant adjudicates temporal and correction semantics.

**Hindsight recall request**: POST `/v1/default/banks/{bank_id}/recall` with query, `types=["world"]`, `budget="mid"`, `max_tokens=1024`, `query_timestamp="2026-02-02T00:00:00Z"`, `prefer_observations=false`, `tags=["jarvis-dev-only","synthetic"]`, `tags_match="all_strict"`, `trace=false`. Questions and parameters must not be adjusted after seeing measured failures without a new documented evaluation version. `query_timestamp` anchors relative time and ranking; **`temporal_window` would only influence ranking, not filter memories**.

**Evidence acceptance**: rank measured from `RecallResponse.results`, not a guessed text answer. Every returned result must be one of five pinned fictional facts, with exact source `document_id`, text, type `world`, version, correction lineage, synthetic source ref and source classification. Duplicate/spoofed/nonfictional inputs fail closed. Dynamic internal Hindsight UUIDs do not form the identity contract; assertion IDs in metadata do.

**Answer acceptance**: a *separately produced* structured JARVIS decision containing `status`, `answer_code`, `evidence_assertion_ids` must match the frozen answer key and cite the exact required facts. No extra obsolete citation is permitted for a current-only decision. Unknown/ambiguous questions require explicit abstention even if recall returns semantically related facts. The scorer **does not** call an LLM, generate a decision, or judge freeform prose, and absence of decisions is `not_evaluated` (not a pass).

### Hard gate criteria

1. **Retrieval coverage**: 7/7 evidence-requiring cases meet their precommitted top-3/top-5 requirements.
2. **Answer correctness and citation**: 9/9 structured decisions exact, with 2/2 required abstentions.
3. **Provenance**: 100% of supplied recalled items validated against pinned identities; any unknown item fails closed.
4. **Operations**: disposable local bank, localhost Docker safety, no owner memory, no paid provider, no consolidation, import once per separately approved run, verified deletion, no retry on failure.
5. **Independence**: only *actual owner-machine server capture* may contribute real recall metrics; successful synthetic mock scoring demonstrates evaluator logic only. There is **no automated promotion** in any case; production canonical SQLCipher remains authoritative.

Strict 7/7 and 9/9 are research acceptance criteria, not a guarantee Hindsight can meet them.

The CLI default prints the frozen nine-question protocol with `status="not_measured"`. It does not access Docker, SQLCipher, Gemini, Hindsight, or the network. A developer may feed **only fictional** candidate JSON via stdin with `--score-stdin`, then independently inspect the result; even a perfect score remains marked `origin="caller_supplied_unverified"` and `real_server_accuracy_verified=false`.

Candidate schema (nine cases, one per pinned `case_id`):

```json
{
  "cases": [
    {
      "case_id": "atlas_current_day",
      "recall": {
        "results": [
          {
            "id": "<ephemeral internal id>",
            "text": "<exact text of pinned Atlas-day-v2 fact>",
            "type": "world",
            "document_id": "jarvis-dev-only-synthetic-workshop-day-v2",
            "metadata": {
              "<exact string keys and values of the pinned fact>": "..."
            }
          }
        ]
      },
      "decision": {
        "status": "answer",
        "answer_code": "sunday",
        "evidence_assertion_ids": ["synthetic-workshop-day-v2"]
      }
    }
  ]
}
```

This is an abbreviated schema example; scoring requires all nine cases. For an abstention, supply `{"status":"abstain","answer_code":null,"evidence_assertion_ids":[]}`. Omit `decision` entirely when only retrieval responses have been captured. Do not manually write guesses to pass the answer gate.

## What this phase does NOT demonstrate

No production integration; no user data; no multilingual or robustness/generalization benchmark beyond the small fiction fixture; no calibrated confidence threshold; no answer-generation quality; no consolidation-based contradiction resolution (intentionally disabled); no quantified latency or cost under real load. A five-fact isolated bank is a narrow deterministic integration probe, **not** deployment acceptance.

Before a new owner-approved live run: review the proposed query/capture harness separately. The next live trial must create a fresh synthetic bank, import once, call read-only recall for the frozen nine queries while the bank exists, store only sanitized synthetic evidence, and confirm cleanup even on failure. Never run the former import probe alone to test retrieval—it deletes the bank before any query can be executed.
