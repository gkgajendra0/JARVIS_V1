# Step 6 — JARVIS Unified Memory: modular hybrid research foundation

**2026-10-18 — Research draft, no production connection or owner memory processing.**

## Decision

A *hybrid architecture* does not imply running all memory products at the
same time. Hindsight already implements semantic, BM25, graph and temporal
retrieval, with fusion/reranking. Graphiti's evolving relation graph and Mem0's
memory-extraction ideas are **alternatives or optional capabilities** to
evaluate, not components deployed by this PR.

**Canonical SQLCipher remains authoritative.** Every retrieval index is
rebuildable and replaceable. Engine-ranked scores do not vote on whether
claims are true; trusted provenance, event lineage, and a separate decision
policy do. No automatic deletion, summarization or production promotion.

## Target architecture

1. **Canonical event store** (current JARVIS SQLCipher): original turn/event
   references, immutable source identity, versions, corrections, effective
   times, consent and later retractions. Nothing in this PR reads that store.
2. **Extraction and admission policy**: candidate preferences/entities/events
   proposed from conversations; no facts admitted unless source and
   uncertainty are checked. Mem0-style ideas, not Mem0 installed.
3. **Retrieval adapters**: begin with Hindsight and a cheap lexical baseline;
   optionally graph/temporal alternatives. Only assertion IDs enter the
   merger; never accept provider-supplied metadata as canonical truth.
4. **Hybrid merger**: rank-only reciprocal rank fusion (RRF, K=60); enforce
   unique provider names and reject duplicate/unrecognized assertion IDs.
   Reject evidence outside an explicitly validated subject/predicate scope.
   Provider agreement improves ranking, **not factual certainty**.
5. **Temporal/version gate**: require the complete validated predecessor
   chain in retrieved evidence, reject conflicting branches/mixed histories.
   No silent borrowing from the complete fictional corpus.
6. **Context builder**: output bounded JSON assertions with source
   references and revisions, not unbounded memory dumps. Scope, safe
   abstention and exact JSON **character** cap; no inaccurate claim that
   character counts equal LLM tokens.
7. **Answering and reflection**: separately measured against human-graded
   or rule-graded answers; no model response is generated by this PR.
8. **Observability and rollback**: privacy-safe diagnostics, opt-in shadow
   comparisons, no automatic read/write integration or switching.

## Implemented here

`src/jarvis/memory/research_hybrid_context.py` is a pure Python,
**synthetic-only** `assemble_context(canonical_synthetic, streams, request)`
contract. Inputs must be typed fictional assertions verified by the
Step 5 provenance/lineage gate. Providers can only suggest *IDs* from the
approved fictional corpus. It handles four logical channels:
`hindsight`, `lexical`, `temporal`, and `relationship`. These are
abstract channels; Graphiti, Mem0 and other external engines have **not**
been installed or connected.

The builder fuses rankings, checks complete source lineage by predicate,
includes only requested subject/predicates, and either outputs bounded
structured JSON or abstains. If multiple requested predicates are present,
fully verified independent groups may be returned while incomplete groups
are explicitly withheld. A tight budget never truncates or quietly rewrites
a correction chain.

`tools/research/step6_hybrid_context_acceptance.py` generates the existing
3,600 fictional structured assertions and executes 240 constructed scope
queries. Simulated channel returns are intentionally split so that no one
channel has the full 3-version history. It checks merged completeness and
rejects an isolated latest fact. **These are deliberately constructed
protocol tests, not Hindsight-at-scale or vendor performance results.**

## Phase gates after this PR

A. Build a provenance-verified **read-only canonical adapter** gated by
explicit owner approval; independently review scope, consent, secrets,
retractions, authentication, backup and rollback.
B. Benchmark *real* Hindsight recall with hundreds/thousands of isolated
fictional facts; measure answer truthfulness, precision/recall, latency,
CPU/RAM and query failures, not just decision-rule correctness.
C. Add an independent keyword/vector baseline, compare with Hindsight using
the same question set, model and machine; only then consider Graphiti/Neo4j
or Mem0 self-hosted if measurable shortcomings remain.
D. Study natural language extraction, ambiguity, temporal conflicts and
active context window effects. Require refusal/abstention for uncertainty.
E. Enable shadow-only JARVIS runtime access behind an explicit feature flag
after threat-model, policy and performance checks. SQLCipher stays source
of truth, no candidate write authority.

Passing this research suite **does not** establish zero hallucinations,
life-long perfect recall, real-provider superiority, large Hindsight server
quality, or permission for production promotion.
