# Decision record: stop the Librarian parallel experiment

**Decision ID:** ADR-LIBRARIAN-001  
**Date:** 2026-11-01  
**Status:** DISCONTINUED / ARCHIVED — do not merge or activate  
**Repository:** `gkgajendra0/JARVIS_V1`  
**Experiment:** draft PR [#304](https://github.com/gkgajendra0/JARVIS_V1/pull/304) on `experiment/librarian-parallel-20261101`  
**Existing Jarvis memory work:** PR [#303](https://github.com/gkgajendra0/JARVIS_V1/pull/303) — completely independent

## 1. Original goal

The user wanted to run **two complete, independent systems** and benchmark them:

- **System A:** Existing Jarvis with its own memory and conversation continuity (PR #303).
- **System B:** The same Jarvis plus the creator's actual **Librarian** shared-memory backend, without removing or replacing Jarvis's memory.

The experiment was supposed to determine, using identical test cases and the same model, whether Librarian genuinely improves correct recall, conversation continuity, correction handling, project isolation, retrieval latency, tokens, reliability and overall answer quality.

**The goal was never to clone Librarian or buy a different Jarvis assistant.**

## 2. Why the experiment was stopped

1. **The actual product was not accessible for installation/testing.** At the decision date, we did not possess a verified official Librarian server package, public source repository, documented MCP endpoint, authentication instructions or tool schema. The creator described a free edition as still in preparation. Without the actual backend, there is no legitimate way to benchmark it.
2. **The website was selling a guided/custom setup, not providing a direct technical download.** The public flow advertised a firm-oriented installation on the customer's server and presented a 12-question “2-minute check,” email follow-up and setup-oriented offers. The separately advertised **“Jarvis in 60 Minutes”** purchase is a different email/calendar assistant kit; it is **not** the Librarian memory engine required here.
3. **No evidence established superiority over our existing Jarvis memory.** Marketing descriptions and demonstrations did not include independently validated, reproducible comparisons against our requirements or PR #303.
4. **Further work had poor return on effort.** Building additional generic infrastructure or completing a paid-sales questionnaire would not solve the missing-product-access problem. It would distract from finishing and measuring PR #303.
5. **No verified price or trial terms for the required Librarian backend.** The user did not want to pay or negotiate for an unproven improvement.

**Important distinction:** We have **not** established that Librarian is fake or non-functional. The evidence only supports: its superiority and installation suitability were **unverified and inaccessible to this experiment**. A long questionnaire or paid offering does not by itself establish fraud.

## 3. What was actually implemented in PR #304

This branch contains an **isolated, synthetic-only MCP experiment harness**, not the creator's Librarian code:

- A Python stdio MCP JSON-RPC transport with initialization, discovery, tool calls, error handling and bounded I/O.
- Explicit `recall`, `remember`, `correct` and `forget` operation mappings with a synthetic namespace and write opt-in.
- Schema preflight, read-only-hint checks (advisory only), source/project provenance checks and rejection of foreign project records.
- An ephemeral **mock server** that is clearly labeled as a fixture, not Librarian.
- Synthetic conversation/event replay, correction, forgetting and isolation tests.
- Fixture/config/tool-schema fingerprints, latency measurements and a strict **future** paired A/B report format.
- Dedicated GitHub Actions checks for the synthetic adapter.

These assets are retained as historical experiment code, **not recommended for production integration** without requalification.

**Do not treat mock-server tests or mock timing numbers as real Librarian performance data.**

## 5. Final decision and next priority

**STOP this experiment. Keep branch/history for reference. Close PR #304 unmerged. Do not activate, purchase or continue the sales questionnaire for now.**

Focus on acceptance testing of **PR #303** and define concrete baseline metrics. Only if that baseline leaves meaningful memory gaps should an alternative backend be considered.

Possible later candidates, for separate evaluation, include a genuinely accessible, self-hostable open-source memory service such as Mem0. This is **not** a decision to install or adopt Mem0; it would need its own license, security, data-handling and benchmark review.

## 6. Conditions required to reopen Librarian evaluation

Reopen only if **all** of the following are satisfied:

1. Obtain an **official, installable backend or usable MCP endpoint** with verified technical documentation and permission to test.
2. Confirm licensing, price, third-party data processing, authentication, retention and deletion guarantees before providing any data.
3. Run the actual backend in a separate, restricted environment with **fictional data only**, and verify persistence, corrections, provenance, isolation and failure recovery.
4. Finish the existing PR #303 benchmark first, then compare both complete systems using identical cases, model settings, repeatability and independently reviewed answer correctness.
5. Require a demonstrable benefit large enough to justify operational complexity, ongoing support and cost.
6. Obtain explicit user approval before any integration into the live Jarvis memory pipeline, changes to PR #303 or payment.

If the creator only offers a sales call or paid configuration service without an independently testable product, **leave this experiment closed**.
